## Source-grounded workflow map

1. **Choose a builder for the learner's need.** The instructor contrasted Framer for hands-on design modification, Lovable for a more guided AI workflow, and v0 for a more technical interface. Treat price, reliability, and interface comparisons as class-time observations, not current guarantees.
2. **Adapt the master prompt before generation.** Set the actual portfolio identity, aesthetic, desired pages, interaction and content. Keep instructions focused on the intended result. Remove or adapt the backend/styling clauses for the chosen platform as directed in class; do not leave conflicting CMS, local-state, cloud, or framework assumptions.
3. **Plan, inspect, then build.** In Lovable, use the plan/discussion step and review what it understood before implementation. The source describes a single detailed prompt as an option, while the class demo also discussed supplying page prompts together; do not require a fixed message count.
4. **Replace placeholders with real portfolio material.** Add project files or working video links where the platform supports them. The instructor recommended YouTube Unlisted or Wistia for playback and noted Google Drive links may not play inline. For multiple replacements, map each placeholder name to its replacement link in one organized document.
5. **Review the generated site and plan revisions.** Check page content, navigation, gallery, video playback, responsive previews, visible placeholders and requested interactions. If a builder lacks a desired feature or blocks an edit, state the target section and desired result clearly; avoid spending credits on piecemeal messages when issues can be grouped.
6. **Position the portfolio around the actual business.** Use relevant services and projects. Class discussion advised against labeling every offering “AI” and described AI video as one vertical within broader production/marketing services when that matches the learner's business.
